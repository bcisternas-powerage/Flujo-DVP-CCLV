Etapa 0 — Ingesta SWIFT (origen de PRCNF e INFWR)

Etapa previa que alimenta al requerimiento IS-1131. El programa heredado IN0050 recibe el archivo de exportación de SWIFT, descompone cada mensaje y graba los archivos PRCNF (cabecera) e INFWR (detalle por tag). Esos archivos son la fuente de datos que el nuevo proceso de IS-1131 leerá para construir el pivote SWF298F.
IN0050 no se modifica. En este requerimiento se consume tal cual: solo se leen los archivos que ya genera. El trabajo nuevo es un proceso que interprete esos mensajes hacia el archivo pivote.

Qué hace IN0050

  • Lee el archivo de exportación SWIFT (bloques {1:F..}, {2:O..} y tags :20:, :32A:, :50:, :59:, :72:...).
  • Detecta el tipo de mensaje (103, 202, 102, 700...) y el submensaje; separa pagos/recepciones, cartas de crédito y otros.
  • Resuelve cuentas y bancos contra tablas del core (ACMST, CUMST, MTABAMST, etc.).
  • Graba la cabecera en PRCNF (subrutina wrtprcnf) y el detalle por tag en INFWR (subrutina wrtinfwr).

Archivos generados que consume IS-1131

ArchivoContenidoCampos clave
PRCNFCabecera: 1 registro por mensaje MT298PRCSRF (sender ref) · PRCSMT (submensaje) · PRCNUM (id único IBS) · PRCDTY/DTM/DTD · PRCTIM

Relación entre archivos: el detalle se enlaza con la cabecera por PRCNF.PRCSRF/PRCSMT = INFWR.INFSRF/INFSST. Esta es la base de las reglas de extracción del pivote.

El flujo MT298 en contexto

Esta etapa es el inicio del flujo MT298 completo: el pago se carga en Web DCV, el DCV gatilla el SWIFT 298, IN0050 genera PRCNF/INFWR, la información se consolida en SWF298F y alimenta al canal para generar la transacción LBTR. Al cierre del día, el proceso caducador depura los pendientes.
